FEATURES-17 — TTT Scene, Life World Scene, Text Widget
======================================================

## Feature 1: TTT Scene

A dedicated scene that fills a 6×4 grid (24 slots) entirely with self-playing
tic-tac-toe games. Each cell runs its own independent game at different paces,
creating a mesmerizing wall of X's and O's.

### Design
- Scene name: "TTT"
- Grid: 6 cols × 4 rows (24 simultaneous games)
- Theme: `neon` — bright X/O marks on dark backgrounds, game-show energy
- Intensity: 8 — moderate pace so games are readable but always moving
- Foreground windows: 0 — full grid, no floating panels
- Ambient preset: `server_room` — low electronic hum fits the constant calculation
- Filter: `['tic_tac_toe']` — only tic-tac-toe activities
- No `slots` array needed — filter already constrains to tic_tac_toe

### Files to change
- `static/js/scenes.js` — add TTT scene object
- `static/js/scenes.js` → `SCENE_SLUGS` import (if slug auto-generated) or
  `server/scene_slugs.py` — add `"ttt"` vanity URL slug

## Feature 3: Text Widget

A new activity type called `text` that displays a shared, editable text box.
When any viewer on the channel types into it, the text appears on all connected
monitors in real time — a persistent shared notepad per channel.

### Design

**Display:**
- A simple text area filling the activity panel
- Monospace font, themed to match the current style
- Subtle blinking cursor indicator when someone is actively typing
- Title bar shows "TEXT" (or a random title from a set: "SHARED PAD", "MEMO",
  "BROADCAST TEXT", "LIVE NOTE", "CHANNEL MSG")

**Behavior:**
- Text state is authoritative on the server (stored per-activity in the channel)
- Typing emits `text:update` events with the full text content (debounced ~300ms)
- Server stores the text and broadcasts to all clients on the channel
- On connect/sync, clients receive the current text content in the activity state
- Text persists as long as the activity is alive; cleared on respawn
- OBS mode: text area is read-only (no cursor, no editing)

**Server generator:**
- `TextActivity` in `server/generators/text.py`
- Unlike other generators, this one does NOT auto-advance frames
- State: `{ "text": "", "last_editor": null, "updated_at": null }`
- `next_frame()` returns current state unchanged (no autonomous updates)
- Receives external text updates via a new method (e.g., `set_text(text, editor)`)

**Socket protocol:**
- Client → Server: `text:update { id, text }` — user typed something
- Server stores in activity state, broadcasts `activity:update` to channel
- No delta protocol needed — text payloads are small

**Activity registration:**
- Add `'text'` to `ACTIVITY_TYPES` in `activityTypes.js`
- Add to `ACTIVITY_CATEGORIES` under a new or existing group
- Add `TextActivity` to `server/activity_registry.py` REGISTRY
- Low weight (0.3) in WEIGHTS — shouldn't dominate random scenes
- Register `activity-text` component in `app.js`

### Files to create
- `server/generators/text.py` — TextActivity generator class
- `static/js/components/activities/Text.js` — Vue component

### Files to modify
- `static/js/activityTypes.js` — add `'text'` to ACTIVITY_TYPES + categories
- `server/activity_registry.py` — register TextActivity, set weight
- `static/js/app.js` — import and register `activity-text` component
- `app.py` — add `text:update` socket event handler
- `static/css/activities.css` — minimal styling for text area
